【パターン1：垂直分解のみ（推奨 ✅）】

┌──────────┐    ┌──────────┐    ┌──────────┐
│Service A │    │Service B │    │Service C │
│ シンプル │    │ シンプル │    │ シンプル │
└──────────┘    └──────────┘    └──────────┘
     ↕              ↕              ↕
  ──────────────────────────────────────
        サービス間の統合

  各サービス内部はシンプル
  → サービス境界が強力な分離メカニズム
  → 複雑性はサービス間の統合に移動


【パターン2：垂直 + 水平（非推奨 ❌）】

┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  Service A   │  │  Service B   │  │  Service C   │
│ ┌──────────┐ │  │ ┌──────────┐ │  │ ┌──────────┐ │
│ │Framework │ │  │ │Framework │ │  │ │Framework │ │
│ ├──────────┤ │  │ ├──────────┤ │  │ ├──────────┤ │
│ │ Adapter  │ │  │ │ Adapter  │ │  │ │ Adapter  │ │
│ ├──────────┤ │  │ ├──────────┤ │  │ ├──────────┤ │
│ │Use Cases │ │  │ │Use Cases │ │  │ │Use Cases │ │
│ ├──────────┤ │  │ ├──────────┤ │  │ ├──────────┤ │
│ │ Entities │ │  │ │ Entities │ │  │ │ Entities │ │
│ └──────────┘ │  │ └──────────┘ │  │ └──────────┘ │
└──────────────┘  └──────────────┘  └──────────────┘
       ↕                ↕                ↕
  ────────────────────────────────────────────────
          サービス間の統合

  各サービス内に4層の構造
  → サービス境界 + 層分離の二重構造
  → 認知負荷とメンテナンスコストの増大
